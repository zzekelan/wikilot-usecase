# DSec

## 身份与用途

DSec 即 **DeepSeek Elastic Compute**，是用于智能体训练和评测的弹性沙箱平台。它管理不同代码仓库、依赖、工具和执行环境，为长时程轨迹提供隔离、日志及抢占后恢复能力。来源：[[wiki/source/大模型报告/deepseek-v4-1-flash|报告]]第 27–29 页。

## 架构如何扩展

| 设计 | 解决的问题 |
| --- | --- |
| scale unit 分片 | 减少单一故障或内存压力波及其他实验 |
| 多副本 placement engine | 用近似资源信息和最终一致性减少全局协调 |
| 节点本地硬准入 | placement 超过资源阈值时拒绝，保证本机安全 |
| sub-NUMA worker VM | 把 CPU/内存与故障局限在局部 NUMA 域 |
| 延迟敏感执行类 | 给评测任务优先资源，降低后台负载干扰 |

报告给出的部署规模为百万级并发沙箱；相似负载下，单物理节点可支持的活动容器从约 1000 提升至 2500 以上。非延迟敏感任务使用 SCHED_IDLE，配合 core scheduling 分隔优先级不同的超线程任务（第 28–29 页）。

## 隔离与失败反馈

每个 sandbox 使用 AppArmor 配置和细粒度 eBPF 网络策略，限制越权和网络泄漏。若 agent 破坏环境导致崩溃，将该轨迹记失败并向 RL 返回后果信号。这样基础设施既执行任务，也参与奖励的可靠性保障（第 29 页）。

[[wiki/concept/后训练与智能体/智能体任务合成|合成任务]]在沙箱内运行；agent sandbox 负责框架与工具，worker container 负责通用控制和轨迹规范化。两者与可抢占 GPU 训练池分离，让长任务能保存完整状态、释放资源并在稍后恢复（第 26–27 页）。
