# Engram

## 身份与作用

Engram 是 DeepSeek 的条件记忆模块，以稀疏查表为模型提供记忆容量，将部分记忆功能与密集计算分开。报告沿用 tokenizer 压缩、多头哈希、上下文感知门控和多分支集成。它按 token/ngram 确定地址，读取可训练嵌入，再结合当前上下文使用，区别于为每个 token 运行整个大表。来源：[[wiki/source/deepseek-v4-1-flash|报告]]第 13 页。

## V4.1-Flash 中的配置

| 项目 | 配置 |
| --- | --- |
| 参数量 | 196B，平均分配给两个模块 |
| 层位置 | 零基编号 1、14，即第 2、15 层 |
| ngram 阶数 | 2、3、4 |
| 哈希头 | 每阶 8 个 |
| 嵌入维度 | 每阶合计 2048 |
| 表大小 | 每头约 16M 条目，表长取互异素数 |
| 精度 | 嵌入表及 key/value 投影用 FP8 |

该版删除原设计的短因果卷积，简化推理实现；嵌入表用[[wiki/concept/Muon与Sinkhorn矩阵优化|Sinkhorn 平衡更新]]，投影矩阵用 Muon（第 13、15 页）。

## 系统实现

确定性索引使查表可在进入目标层前启动。部署时可从 host memory 经 RDMA 预取，和前层计算重叠；训练时表按行分片，状态进一步分片，反向梯度先缓冲、后回传，尽量和视觉阶段重叠。RL rollout 将表常驻 GPU，以减轻主机内存碎片压力（第 13、18 页）。

Engram 的参数应与主干分开记账：报告的 552B 主干之外还有 196B Engram。大量查表参数增加容量，但其访问模式与[[wiki/concept/MoE与多模态负载均衡|MoE 专家计算]]不同。
