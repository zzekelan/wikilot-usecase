# 推理力度与测试时计算

## 测试时计算是什么

模型权重固定后，仍可通过更多推理 token、工具探索、重复尝试或协作分配额外计算。推理力度（Reasoning Effort）把这种资源偏好作为输入条件，让同一个模型选择不同程度的检查和探索。来源：[[wiki/source/deepseek-v4-1-flash|报告]]第 29–30、34–36 页。

## 通过奖励学会控制长度

报告使用 b∈{1,…,100}，在 system prompt 加入力度说明。同问题、同 b 的回答构成子组，组内奖励中心化形成相对优势；不同力度不直接互相比奖励。长度奖励为：

\[
r_{len}(\ell,b)=-\min\{C_{max},k(b)\ell/L_{norm}\},\qquad
k(b)=k_0\exp[-(b-b_{min})/\tau].
\]

b 越高，token 惩罚越弱；增加 τ 个力度单位，惩罚系数乘 e⁻¹。它是行为偏好，而非硬 token 上限。报告 API low/high/max 对应 50/75/100（第 29–30 页）。

## 指数惩罚为什么自然

附录 C 设问题解决概率为 p_x(ℓ)，在惩罚未封顶的区间优化 p_x(ℓ)−k(b)ℓ/L_norm。内部最优满足 p′_x(ℓ*)=k(b)/L_norm；若边际收益约为 a_x·exp(−ℓ/s_x)，则：

\[
\ell_x^*(b)\approx s_x\log(a_xL_{norm}/k_0)+\frac{s_x}{\tau}(b-b_{min}).
\]

指数递减惩罚因而对应局部近似线性的长度控制。该推导依赖内部最优和未触 cap；cap 之后边际长度惩罚为零（第 49–51 页）。

## 如何选力度

报告图 9：b=25→100，八项推理均值 67.1→76.3、DeepSWE 66.0→74.2、Terminal-Bench 2.1 为 82.4→90.6，输出约增至 2.5 倍。附录图 11 中，不同框架的准确率存在中间下跌和平台，因此更高力度不是每个任务上的必胜选项（第 34–35、48–49 页）。

实际应在任务与框架固定时画质量–成本曲线，选择收益明显的预算点；对最难任务再提高上限。[[wiki/concept/Softmax与温度采样|采样温度]]控制随机性，力度控制学到的推理行为，两者分工不同。
