# 智能体框架与评测协议

## 模型之外还有什么

智能体框架（scaffold/harness）负责系统提示、工具定义、执行循环、上下文压缩、任务结束条件和资源预算。相同模型放入不同框架，能看到的状态、可用行动和失败恢复方式不同，最终表现也会变化。来源：[[wiki/source/deepseek-v4-1-flash|报告]]第 34–35、47–48 页。

## 复现评测需要记录的配置

| 维度 | 应记录内容 |
| --- | --- |
| 模型 | checkpoint、基础/后训练版本、推理力度 |
| 框架 | 名称、版本/commit、原生 prompt、工具 schema |
| 生成 | temperature、top-p、上下文窗口、最大轮数 |
| 环境 | OS/容器、依赖、网络权限、CPU/GPU/时间限制 |
| 数据 | 基准版本、子集筛选、题目数 |
| 统计 | 每题采样数、评分规则、失败处理与区间 |

## 同一模型的框架差异

报告表 4 固定模型和采样设置，仅变周围框架。DeepSWE v1.1 从 OpenCode 的 65.5 到 mini-SWE 的 74.2；Terminal-Bench v2.1 从 Codex 的 84.1 到 DSH Minimal 的 90.6。工具更多不保证更高分；简单工具循环可能更贴合特定任务（第 35 页）。

共同设置为 effort=100、1M context、temperature=1、top-p=.95、max_steps=500。DeepSWE 每题 N=8、Terminal 每题 N=3，用来估计单次结果；这不是 Pass@8/Pass@3。完整版本和数值见[[wiki/source/deepseek-v4-1-flash|来源页]]表 4–5。

## 公平比较的关键

在等模型、等预算下比较框架，回答“交互设计有什么影响”；在统一框架下比较模型，回答“模型能力有什么差异”。两者都改变时得到的是联合系统对比。网络权限、缓存清理和评分器隔离也是协议的一部分，因为它们决定模型完成的是预定任务还是绕过评分（第 32–35 页）。
