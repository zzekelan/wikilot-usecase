# 分布式训练与推理解耦

## 解耦的目的

不同模块具有不同资源特征：视觉处理有图像 I/O 和变长输入，语言主干有规则矩阵计算，条件记忆有稀疏查表，prefill/decode 的计算和访存比例也不同。解耦让它们分别扩展，再以流水线、预取和通信重叠连接。来源：[[wiki/source/deepseek-v4-1-flash|报告]]第 16–19 页。

## 多模态训练的三阶段

视觉编码器位于 LLM 参数树之外，每步分为“视觉前向→LLM 前向/反向→视觉反向”。图像负载均衡限制在视觉阶段，语言阶段沿用文本训练的并行策略。对比学习中，视觉特征 all-gather 可与文本前向重叠，文本特征 all-gather 可与文本反向重叠（第 16–17 页）。

百万 token 序列里的图像按上下文并行 rank 均衡分片，每图仅加载一次；rollout 增量传图并复用 CPU 预处理。报告用 Nρ/B_IO < NC/B_GPU 表达 I/O 能被计算掩盖的条件，约去 N 后，核心是每 token 原始字节数 ρ 与每 token 计算量 C 的比例（第 17 页）。

## 跨层共享怎样跨设备实现

[[wiki/concept/CSA2压缩稀疏注意力|CSA2]]的共享层可能位于不同 pipeline stage。报告使用：

- shadow indexer：每个相关 stage 有轻量执行副本，单一 owner 负责参数优化与 checkpoint。
- 通信载荷扩展：在现有点对点路径上传递中间状态和稀疏索引，并匹配上下文分片。
- micro-batch 生命周期管理：追踪并发前向、重算和反向的消费者，最后一次使用后才释放共享状态。

这使共享语义不依赖物理层布局（第 17–18 页）。[[wiki/entity/Engram|Engram]]则依靠行分片、提前取表和梯度延后回传减少等待。

## 推理的 EPD 与内核融合

EPD（Encoder–Prefill–Decode）让视觉编码、输入预填充和输出解码独立扩展，避免一种负载阻塞所有阶段。融合内核则减少 kernel 启动与显存往返：报告的 CSA2 Reuse 层 prefill 为 15 个 kernel、decode 为 11 个（第 18–19 页）。[[wiki/concept/Single-Pass-mHC|Single-Pass mHC]]是“先改依赖关系，再做融合”的例子。

解耦优化调度粒度，融合优化模块内部执行；两者是不同层次的互补设计。
