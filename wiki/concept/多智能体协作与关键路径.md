# 多智能体协作与关键路径

## 协作如何产生收益

多智能体把复杂任务拆成可并行工作，由主 agent 汇总结果。收益来自并行探索、分工和交叉检查；成本来自重复劳动、消息往返、上下文复制与写入冲突。[[wiki/entity/DeepSeek-Harness|DeepSeek Harness]]的 Agent Team 使用共享仓库、任务板和持久 mailbox 组织这些活动。来源：[[wiki/source/deepseek-v4-1-flash|报告]]第 35–36 页。

建议写入范围（advisory write scope）帮助协调，但不等于强制锁；lead 仍需检查合并后的代码与测试结果。

## 关键路径比 token 总量更能描述延迟

报告把生成、工具执行和协作依赖组织成有向无环图（DAG）。给 token 事件按固定 prefill/decode 速率赋成本，工具事件用实测时间，最长依赖路径为 derived latency。

例如两项独立子任务各需 10 分钟、汇总需 2 分钟：完全串行是 22 分钟，理想并行为 12 分钟。总工作量并未减半，但关键路径缩短。奖励加入任务成绩、协作 bonus 与 derived-latency penalty，以鼓励有用分工、抑制无意义同步（第 36 页）。

## 报告的初步实验

- ProgramBench 先筛为参考解通过率≥95% 的 172 个 golden 任务，每配置计划 516 rollouts；Almost@1 衡量单次 rollout 得分≥.95 的比例。multi 从 1h 的 13.59% 到 8h 峰值 30.04%，single 对应 12.79%/20.39%。
- FrontierSWE v2 使用公开 no-GPU 子集、Mean@5；1h→20h，multi 为 13.50→32.90，single 为 10.50→28.20。

它扩展了[[wiki/concept/推理力度与测试时计算|测试时计算]]的分配方式：单 agent 可以想更久，多个 agent 则还可以并行工作。
