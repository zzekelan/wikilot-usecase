# 强化学习（RL）

## 定义与范围

**强化学习**（Reinforcement Learning，RL）以行动带来的回报为学习信号，优化决策策略。它是一般的学习范式，不只用于语言模型，也不等于 RLHF、PPO 或某个后训练阶段。本页给出基本框架和语言模型中的对应关系；具体更新算法与系统调度分别讨论。

## 核心对象

| 对象 | 含义 | 语言模型/智能体实例 |
| --- | --- | --- |
| 状态或观测 | 作出决策时可用的信息 | 提示、已有回答、工具返回 |
| 行动 | 策略作出的选择 | 下一个 token，或一轮工具调用 |
| 策略 π(a\|s) | 给定状态的行动概率 | 模型的条件生成分布 |
| 环境 | 接受行动并反馈 | 文本交互、代码沙箱 |
| 奖励 | 用于衡量行动或结果的数值反馈 | 答案正确率、测试结果、偏好模型评分 |
| 回报 | 一段轨迹上的累计奖励 | 最终完成任务减去成本 |

按决策过程的通用记法，目标为：

\[
\max_\theta J(\theta)=\mathbb E_{\tau\sim\pi_\theta}\!\left[\sum_{t=0}^{T-1}\gamma^t r_t\right],\qquad 0\leq\gamma\leq1.
\]

这里 τ 是交互轨迹，γ 是折扣系数；有限回合可取 γ=1。上述是概念框架，具体算法用采样估计和替代目标实现；[[wiki/source/后训练与强化学习/ppo原始论文|PPO 原论文]] §2、§5 给出策略梯度、优势估计及更新循环（第 2–5 页）。

## 为什么不需要逐步标准答案

策略梯度的一种估计形式是 \(\hat{\mathbb E}[\nabla_\theta\log\pi_\theta(a_t|s_t)\hat A_t]\)：提高正优势行动的概率、降低负优势行动的概率（PPO §2.1，式 1）。优势衡量“比基准好多少”，不等于未经处理的奖励。

例如代码任务只在运行测试后给分，模型仍可根据整段轨迹的反馈更新行为；但如何把最终结果归因到早期行动，是信用分配问题。[[wiki/concept/后训练与智能体/监督微调SFT|SFT]]则直接提高示范 token 的概率。

## 语言模型中的不同实现

- **RLHF**：人类比较先训练奖励模型，再优化策略。[[wiki/source/后训练与强化学习/instructgpt|InstructGPT]] §3.5 用 PPO 和相对监督策略的 KL 惩罚（第 8–9 页）。
- **可验证任务反馈**：正确性、测试或环境验证器直接参与构造奖励。[[wiki/concept/后训练与智能体/任务验证|任务验证]]负责反馈质量，而不是替代优化算法。
- **PPO**：一种控制更新幅度的算法，不代表所有 RL 都需要其裁剪目标；详见[[wiki/source/后训练与强化学习/ppo原始论文|原始方法]]。

动作粒度取决于建模方式：InstructGPT 把完整回答视为 bandit 环境的一次响应，同时在训练中按 token 处理概率及 KL（第 9 页）。不能把所有语言模型 RL 都说成多轮环境规划。

## 限制与关系

奖励只是目标的代理。错误验证器或可投机的奖励会把优化引向错误行为，参见[[wiki/concept/评测方法/奖励投机|奖励投机]]。采样来自当前还是旧策略，则影响[[wiki/concept/后训练与智能体/离策略样本|离策略样本处理]]，与奖励是否来自人类是不同维度。

[[wiki/source/大模型报告/deepseek-v4-1-flash|DeepSeek 报告]]的 RL 工程包括长尾调度、陈旧 token 屏蔽和力度相关奖励（第 29–31 页）；这些是 RL 在特定训练系统中的实现，不应合并成 RL 的定义。
