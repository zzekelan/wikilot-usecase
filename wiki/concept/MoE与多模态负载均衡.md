# MoE 与多模态负载均衡

## 稀疏专家模型

混合专家（Mixture-of-Experts，MoE）用多个专家子网络替代单一前馈网络，由路由器为每个 token 选择少量专家。共享专家处理通用模式，路由专家提供条件计算。因此总参数容量与每 token 激活量可以相差很大。来源：[[wiki/source/deepseek-v4-1-flash|报告]]第 7–8、22 页。

V4.1-Flash 每层有 **1 个共享专家和 384 个路由专家**，每 token 激活其中 **6 个路由专家**；专家中间维 2304，使用带阈值 10 clamping 的 SwiGLU。该门控非线性建立在[[wiki/concept/非线性表示与归一化|MLP 表示学习]]之上（第 22 页）。

## 为什么要负载均衡

如果大量 token 都选同一专家，一些设备过忙而其他闲置，吞吐下降；某些专家也得不到足够训练。平衡所有 token 的总量仍可能掩盖模态差异：图像偏向一组专家、文本偏向另一组时，两类 token 内部的偏斜可以相互抵消。

报告对文本、图像分别维护专家校正偏置：

1. token 路由时使用其模态对应的偏置，调整**专家选择**。
2. 混合已选专家输出时仍用原始路由分数。
3. 每步根据各模态专家负载独立更新偏置。

这把负载调节与输出权重分开，降低不同模态互相遮蔽的影响。来源：第 8 页。

## “无辅助损失”的具体含义

专家级平衡采用偏置反馈，偏置更新速率 .001；报告仍保留权重 .0001 的序列级平衡损失，避免单条序列极端失衡（第 22 页）。因此方法名 auxiliary-loss-free 指特定平衡机制，不是整个训练没有任何平衡项。

结合[[wiki/concept/CED因果编码器解码器|CED]]，模型还让 prefill/decode 执行不同计算范围，形成 8B/16B 的激活口径；这与专家路由稀疏性共同决定单 token 计算量。
