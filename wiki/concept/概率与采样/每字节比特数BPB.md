# 每字节比特数（BPB）

## 定义与范围

**每字节比特数**（Bits per Byte，BPB）把文本的负对数概率换算成 bit，再除以对应的字节数 B：

\[
\mathrm{BPB}=-\frac1B\sum_{t=1}^{T}\log_2 p(x_t\mid x_{<t}).
\]

B 必须是与计分 token 对应的文本字节数，而不是字符数或 token 数；需要明确编码和文本预处理。公式是对概率计分口径的补充说明。[[wiki/source/大模型报告/deepseek-v4-1-flash|DeepSeek 报告]]图 6 使用 BPB 报告内部留出语料的概率建模结果（第 25 页）。

## 为什么按字节归一化

[[wiki/concept/概率与采样/困惑度PPL|PPL]]使用 token 作为平均单位，单位随 tokenizer 改变。BPB 把分母改为同一文本的字节长度，使计量单位更统一；它不消除编码、上下文、预处理、特殊 token 和边界处理造成的差异，也不保证不同分词模型的概率计分过程完全等价。

例如某段 100 字节文本的累计负对数概率为 200 bit，则 BPB=2。不能仅凭某一个 token 的概率为 0.5，就说整段文本 BPB=1。

## 报告中的实例

DeepSeek 图 6 中 V4.1-Flash-Base 在内部文档、内部代码仓库、学术资料上的 BPB 分别为 **0.564、0.1443、0.4305**，越低越好；这些来自不同语料，不能只用数值大小比较模型在哪种任务上更聪明。完整模型对照、百分比计算与内部数据集未公开信息见[[wiki/source/大模型报告/deepseek-v4-1-flash|来源页 §四]]。

更低 BPB 是对该留出文本赋予更高概率的证据，不直接证明模型能独立完成研发或代码任务。任务能力需要另行查看[[wiki/concept/评测方法/评测协议|任务指标和评测协议]]。

## 与其他概率指标的关系

BPB、[[wiki/concept/概率与采样/交叉熵|交叉熵]]和 PPL 共享负对数概率基础，但归一化与数值尺度不同。换算需要知道 token 数与字节数，见[[wiki/synthesis/学习与表示/交叉熵-PPL与BPB的换算|指标换算]]。
